# 工程账本策略

## 目的

四个文件是仓库内的项目控制面，用于减少跨会话上下文恢复、重复审计和相互矛盾的项目口径。它们是索引和已审查事实，不是聊天记录归档，也不能替代源码、diff 和实验原始证据。

## 文件职责

### `PROJECT_STATE.md`

记录当前快照：

- 项目目标；
- 当前阶段和工作分支；
- 已实现并验证；
- 已实现但证据不足；
- 正在进行；
- 当前阻塞；
- 下一道唯一门禁。

允许覆盖旧的“当前状态”，但必须更新日期、commit/worktree 和证据入口。

### `ARCHITECTURE.md`

记录长期稳定结构：

- 系统边界和运行时数据流；
- 模块职责和集成位置；
- 关键状态、不变量和错误传播；
- 允许/禁止修改边界；
- 已知限制。

只记录当前源码可验证的结构。讨论方案必须明确标为 proposed，不得混入已实现架构。

### `DECISIONS.md`

追加式决策日志。每条至少包含：

- 编号、日期、状态；
- 背景和问题；
- 决策；
- 被否决方案及原因；
- 代价、适用范围和失效条件；
- 证据和关联 commit；
- supersedes / superseded by。

不得删除历史决策。变化通过新决策 supersede 旧决策。

### `EXPERIMENTS.md`

追加式实验索引。每条至少包含：

- 编号和状态：planned / running / valid / invalid；
- 问题、baseline、variants；
- 模型、硬件、系统、构建、commit/worktree；
- workload、预热、重复、顺序；
- 正确性门槛和指标定义；
- runner、原始日志、解析结果和哈希入口；
- 结果、限制和可支持的结论。

不得复制大日志，不得记录无法追溯的数字，不得用单次或失败运行支撑正式结论。

## 读取矩阵

- `contract`：PROJECT_STATE + ARCHITECTURE + DECISIONS；
- `audit`：前三个，涉及实验可信度时加 EXPERIMENTS；
- `implement`：前三个，确认已有边界和被否决方案；
- `review` / `review-fix`：前三个，必要时核对实验账本；
- `script`：全部；
- `memory`：全部。

## 事实优先级

1. 当前源码、当前 diff、实际测试/实验原始证据；
2. 当前 commit、构建产物和机器可读元数据；
3. 工程账本；
4. README、设计文档和历史总结；
5. 聊天记录。

冲突时不得“自动调和”。必须指出哪个账本条目陈旧，并以更高优先级证据为准。

## 普通任务的账本影响

普通任务不自动写账本。只有出现以下情况时，在最终输出中给出一行建议：

- 项目阶段或阻塞状态改变 → `PROJECT_STATE.md`；
- 已实现的模块边界、数据流或不变量改变 → `ARCHITECTURE.md`；
- 接受、否决或替代一项关键技术选择 → `DECISIONS.md`；
- 新增或完成一个正式实验协议/结果 → `EXPERIMENTS.md`。

无实质影响时不输出该栏目。
