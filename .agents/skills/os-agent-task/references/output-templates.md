# 输出模板

只保留有内容的栏目。结论先行，避免重复任务背景。普通模式只有确有必要时追加一行 `工程账本影响`。

## contract

```text
任务：<结果目标>

必要上下文：
- <只写影响判断的当前事实>

范围：
- 允许：<文件/模块或只读范围>
- 禁止：<本轮特殊禁止项>

关键要求：
- <少数影响正确性的要求>

验收标准：
- <机器可判定条件>

输出：
- <修改、验证和未确认事项>
```

## audit

```text
结论：<建议实现/不建议/证据不足>

当前事实与调用链：
- ...

主要问题与证据：
- ...

方案评估：
- 收益：...
- 代价/风险：...
- 失效场景：...

最小接入位置：
- ...

最关键下一步：...
```

## implement

```text
结论：<已完成/证据不足/未完成>

修改：
- <文件：行为变化>

验证：
- <命令或 target：PASS/FAIL>

未验证：
- <用户长测或缺少环境>

风险：
- ...

git diff --stat：...
git status --short：...

工程账本影响：<仅在需要时>
最关键下一步：...
```

## review

```text
结论：<通过/有非阻塞问题/有阻塞问题/证据不足>

阻塞问题：
- <文件/函数/原因/影响>

非阻塞问题：
- ...

已有证据：
- ...

缺失证据：
- ...

工程账本影响：<仅在需要时>
最小下一动作：...
```

## review-fix

```text
结论：<阻塞项已修复/仍有阻塞>

- 阻塞项 A → 修改 ... → 验证 ...
- 阻塞项 B → 修改 ... → 验证 ...

未处理：
- <非本轮范围或审查结论不成立>

工程账本影响：<仅在需要时>
当前是否可进入下一验证：<是/否>
```

## script

```text
结论：<脚本已完成并通过静态/短测>

文件：
- ...

参数与输出：
- ...

PASS/FAIL 规则：
- ...

静态/短测：
- ...

用户正式执行：
<命令>

结果提取：
<命令>

工程账本影响：<仅在形成正式协议或结果入口时>
```

## memory

```text
结论：<已初始化/账本一致/已更新/有冲突/证据不足>

文件：
- <文件：创建或更新内容>

依据：
- <源码、commit、diff、测试或实验证据>

未写入：
- <因证据不足拒绝记录的事项>

git diff --stat：...
git status --short：...
```
